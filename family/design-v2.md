## 1. 同类系统对标研究

设计前先看了市面上真实存在的同类产品与相关研究，避免重复造轮子、也避免踩别人踩过的坑。

### 1.1 产品对标

| 产品 / 研究 | 核心机制 | 可借鉴之处 | 需要规避的风险 |
|------------|---------|-----------|--------------|
| **ClassDojo / 班级优化大师** | 老师点一下就给孩子加/减「行为分」，全班可见 | 反馈必须**即时**（点完 0.5 秒内看到变化） | 公开排名、标签化在国内外都引发过争议；**绝不能让孩子之间横向比较** |
| **Habitica** | 把生活任务游戏化，有连击、装备、公会 | 连击（streak）对坚持的作用极强；升级/徽章带来「非金钱」满足感 | 规则太复杂会崩，孩子 3 天就放弃；也容易被钻空子 |
| **Greenlight / BusyKid**（美国青少年借记卡） | 做完家务 → 家长打钱 → 孩子可存/花/捐 | **存钱有利息**这一点极有效；家长审批环节天然存在 | 过早、全面地货币化，会把「帮忙做家务」变成「雇佣关系」 |
| **FamZoo** | 家庭虚拟银行，家长可自己设存款利率 | 「梦想账户 + 月息」模型，让延迟满足看得见 | 利率设太高会变成刷分套利 |
| **代币制（Token Economy）**，行为分析经典范式 | 目标行为 → 代币 → 兑换实物/特权 | **即时、具体、兑换物是孩子真正想要的**——这是代币制成立的三个前提 | 代币贬值（发太多）和兑换物失效（孩子不想要了）是两个典型死因 |
| **自我决定理论（Deci & Ryan）** | 人有自主、胜任、归属三种内在需要 | 奖励要做得像「**信息反馈**」（你进步了）而不是「**控制手段**」（你得听话） | **过度理由效应**：把本来就喜欢的事（如阅读、弹琴）用钱砸，反而会削弱内在动机 |

### 1.2 三条被反复验证的结论

1. **即时反馈 > 奖励大小**。孩子对「现在就看到 +5」的敏感度，远高于「攒到 100 分能换什么」。
2. **奖励必须逐步撤除（fading）**。长期固定的外部奖励一定会削弱内在动机，所以 v1 里的「三阶段退出机制」不是可选项，而是必需品——v2 把它落成了具体的时间表。
3. **积分制最常见的真实死因是「通胀」**：任务越加越多、积分越给越松、商品价格不敢涨，最后积分变成废纸，系统在一个月内失去信用而崩塌。v2 专门为此做了一个监控看板。

## 2. 系统架构

### 2.1 角色与视图

```
┌─────────────────────────────────────────────────┐
│                   成长工具箱                      │
├──────────────────────┬──────────────────────────┤
│      孩子端 🌟        │       家长端 🛠（PIN 保护） │
├──────────────────────┼──────────────────────────┤
│ 📅 今日  —— 打卡       │ ✅ 审核 —— 待审/批量/抽检  │
│ 🎁 商城  —— 兑换       │ 🤝 约定 —— 信任分级/承诺账 │
│ 💰 我的  —— 账本/心愿   │ 📊 看板 —— 通胀/趋势/热力图│
│ 🏅 成就  —— 徽章墙      │ ⚙️ 设置 —— 配置/编辑/备份  │
└──────────────────────┴──────────────────────────┘
```

### 2.2 分层结构

```
视图层（9 个 view 函数，只负责拼 HTML 字符串）
        ↑ render() 统一调度
状态层（UI = { view, kidTab, parentTab, shopTier, parentUnlocked }）
        ↑
引擎层（积分引擎 · 等级引擎 · 徽章引擎 · 结算引擎）
        ↑
数据层（DB，单个 JSON 文档，存 localStorage: growth_kit_v2）
```

**为什么这样分层**：整个系统没有服务器、没有框架，靠的就是「所有改动 → 改 DB → saveDB() → render()」这一条单循环。任何一次操作都不会出现「界面和数据库不一致」的情况，这也让它极其好维护——孩子不会遇到「点不动」的状态。

### 2.3 积分引擎（系统的核心）

每一次积分变动都必须**同时写两处**：

| 写入位置 | 内容 | 作用 |
|---------|------|------|
| `DB.account` | 当前余额 | 显示、兑换判断 |
| `DB.ledger` | 一条流水（时间/类型/分数/说明/关联对象） | 对账、审计、防「分怎么少了」的纠纷 |

**铁律：余额只能由账本推导出来，不能凭空修改。** 家长想「给孩子加 100 分」也必须走一笔「调整」流水，孩子能看见。这条规则是整套系统可信度的地基。

## 3. 机制设计

### 3.1 任务与积分

四类（沿用 v1）：

| 类别 | 代表任务 | 单次分值 |
|------|---------|---------|
| 📘 学业 | 晚托班完成作业、加练、学而思、新概念、错题整理 | 3–5 分 |
| 🎵 素养 | 琵琶弹奏、单杠悬吊、跳绳 | 2–5 分 |
| 🏠 生活 | 一个人睡觉、叠被子、扫地擦桌 | 2–8 分 |
| ⚡ 挑战 | 阶段性目标（如连续 7 天自己睡） | 一次性高分 |

**分级任务**：像「琵琶弹奏」不是一个固定分，而是给两档——「30 分钟以上 +5」「15–30 分钟 +2」。让孩子自己选档，比「做没做」的二元判断舒服得多，也顺带训练了自我评估。

### 3.2 信任分级与免审限额（v2 新增）

**v1 的痛点**：每一条打卡都要家长点一次审核，家长一天要审 15 次，三天就烦了，系统随之停摆。**家长的时间成本是这套系统最容易被低估的失败原因。**

v2 的解法：

| 信任等级 | 适用任务 | 家长要做什么 |
|---------|---------|------------|
| 🟢 已信任 | 已稳定做对 2 周以上的任务 | **不用管**，自动通过 |
| 🟡 观察期 | 新任务，或最近出过问题的任务 | 需要审核 |
| 🔴 需审核 | 高分值、易造假的任务（如「一个人睡觉」） | 必须审核 |

再加上一层**免审限额**：每天自动通过的积分不超过 12 分、次数不超过 6 次。超过限额的部分自动转为待审核。

这样日常家长的实际工作量从「15 次/天」降到「**2–3 次/天**」，系统才能活得下去。

### 3.3 抽检与证据（v2 新增）

- 对「已信任」的任务按 **15% 概率**随机抽检。被抽到的自动通过记录，家长可以复核。
- 复核结果两种：确认（保持信任）或撤销（**降级为观察期**）。
- 抽检的价值不在抓错，而在于**让孩子知道「可能会被查」**。这一点点不确定性能大幅降低虚报率。

### 3.4 存钱目标 / 梦想账户月息（v2 新增，借鉴 Greenlight / FamZoo）

孩子可以设一个「想要的大目标」（比如一盒新拼豆 88 元），系统显示进度条。核心是两条：

1. **零花钱自动分账**：到手的钱按比例分「自由花」和「梦想储蓄」。
2. **梦想账户按月结息**：每月结算一次利息，让「不花掉」这件事本身有回报。

这比单纯说「你要存钱」有效得多——它把抽象的延迟满足变成了**看得见的、每月长一点点的进度条**。

### 3.5 家长承诺账（v2 新增）

这是 v1 里最有价值、但最容易被忽略的一点，v2 把它做成了功能：**家长也可以被「扣分」。**

| 场景 | 家长端 | 孩子端 |
|------|-------|-------|
| 答应周末去公园但没去 | 记一笔承诺未履行 | **孩子能看到** |
| 兑换申请超过 24 小时没处理 | 记一笔延迟 | 孩子能看到倒计时 |

理由很实在：**一个只约束孩子、不约束大人的系统，孩子三天就能识破并拒绝配合。** 契约必须是对等的。

### 3.6 通胀监控看板（v2 新增）

每月自动算三个指标，摆在家长端看板上：

| 指标 | 健康区间 | 超标意味着 |
|------|---------|-----------|
| **积分发放量** | 环比波动 ±30% 内 | 发太松了，积分要贬值 |
| **积分流通率**（已兑换 / 已发放） | 40%–75% | 太高=商品太便宜；太低=商品不吸引人 |
| **单任务均价** | — | 悄悄给高分 = 隐性通胀 |

**这是整套系统里最「不像儿童产品」的设计，但恰恰是最重要的一条。** 大多数家庭积分制不是死于孩子不配合，而是死于三个月后积分不值钱了。

### 3.7 等级 / 徽章 / 连续打卡

- **等级**：按「累计赚取」（而不是当前余额）升级。这样孩子花钱不会掉级——掉级这件事对动机会造成很奇怪的伤害。
- **连续打卡（streak）**：连续天数越多，徽章越稀有。
- **徽章**：不涉及积分，纯粹是荣誉。避免「所有好行为都要用钱标价」。

### 3.8 商城六层（沿用 v1）

| 层级 | 内容 | 性质 |
|------|------|------|
| ⭐ 拼豆专区 | 拼豆材料、图案 | 核心激励锚点 |
| 🍬 即时 | 小零食、贴纸 | 低门槛，快速兑现 |
| 🎡 短期 | 一次游乐园、看电影 | 周级目标 |
| 🎁 长期 | 大玩具、夏令营 | 月级目标（配合存钱目标） |
| 💰 零花钱 | 按比例兑成现金 | 财商训练 |
| 👑 特权 | 晚睡 30 分钟、决定周末吃什么 | **最关键的一类** |

**特权不能用钱买。** 它是孩子真正在意的东西，而且零成本——这也是「逐步撤除外部奖励」时最好用的过渡物。

## 4. 防作弊与公平性

| 风险 | 对策 |
|------|------|
| 孩子虚报 | 高价值任务必须审核；低价值任务靠抽检 |
| 家长随手加/减分 | 所有变动必须走账本，孩子端可见 |
| 家长临时改规则 | 规则修改在「约定」页留痕，孩子端能查到 |
| 孩子只挑低分任务刷分 | 设「每日封顶」+ 类别均衡提示 |
| 兑换被无限拖延 | 家长 24 小时未处理计入承诺账 |
| 多家长口径不一 | 双家长模式（dualRate），规则以系统为准，不靠记忆 |

## 5. 数据安全与备份

系统全部数据在家里这台设备的浏览器本地（localStorage），**不上传任何服务器**，也不需要注册。好处是隐私安全、离线可用；代价是清浏览器数据会丢。

所以 v2 提供了三层备份：

1. **导出 JSON**：完整备份，可原样导入恢复。
2. **导出 CSV**：账本流水，方便用 Excel 看。
3. **打印卡币 / 公约 / 周报**：实物留档。孩子每赚到一档积分，可以打印一张卡片当「实物奖状」。

**换设备迁移**：旧设备导出 JSON → 新设备导入即可，含全部历史记录。

## 6. 上线首月运行手册

**这一节比功能更重要。** 大多数同类系统不是被孩子放弃的，是被家长的「一次全上」压垮的。

### 第 1 周：只做减法
- 任务只上 **6–8 个**，挑最容易做到、最不容易争议的（如叠被子、扫地、加练）。
- 商品只开 **3 个**：一个 5 分以内的即时奖励、一个拼豆相关、一个特权。
- 家长端**关掉免审限额**，全部人工审核，先建立「说到做到」的信用。
- 目标：让孩子在 3 天内体会到「我今天做的事，晚上就变成了分」。

### 第 2 周：引入信任
- 把已经稳定完成的任务设为「已信任」。
- 打开免审限额。家长工作量应当降到每天 5 分钟以内。
- **第一周的日报/周报打印出来给孩子看**，这比任何说教有用。

### 第 3–4 周：引入延迟满足
- 开放「存钱目标」和梦想账户月息。
- 把任务扩展到全部 17 项左右。
- 做第一次月度复盘：看通胀看板，如果积分发放量比上月涨了 50% 以上，就该收紧任务分值或提高商品价格。

### 长期：每 4 周一次复盘
看三张表——本周赚了多少、完成任务数、余额趋势。**奖励和分值调整要一起调，不能只调一边。**

## 7. 常见坑与对策

| 坑 | 表现 | 对策 |
|----|------|------|
| **通胀** | 三个月后孩子觉得「分不值钱」 | 通胀看板 + 分值商品同步调整 |
| **家长成瓶颈** | 待审列表积压，孩子没耐心 | 信任分级 + 免审限额 + 批量审核 |
| **过度货币化** | 孩子做任何事都先问「给几分」 | 特权类奖励 + 三阶段退出 + 对已有兴趣的事不再加分 |
| **规则不对等** | 孩子说「你们大人怎么不用做」 | 家长承诺账 |
| **一次性全上** | 第一周就 20 个任务，家长崩溃 | 首月运行手册 |
| **横向比较** | 孩子问「班里有同学有多少分」 | 系统内不设任何排名 |
| **数据丢失** | 清理浏览器后全没了 | 三级备份 + 定期导出 |

## 8. 三阶段退出机制（沿用 v1，v2 补充时间表）

这套系统**的终点是它自己不再被需要**。

| 阶段 | 时间 | 特征 | 做法 |
|------|------|------|------|
| **一、外部奖励** | 第 1–8 周 | 靠积分驱动行为 | 即时反馈，分数给足 |
| **二、混合** | 第 9–20 周 | 部分行为已自动化 | 降低分值、换成特权、引入自我记录 |
| **三、内化** | 第 21 周以后 | 行为不再依赖积分 | 保留「成就墙」和结息账户，取消大多数日常积分 |

判断标准很简单：**某个行为连续 4 周不用提醒就能做到，就可以开始给它降分。** 到第三阶段，孩子留下来的应该是习惯和成就墙，而不是积分表。

## 9. 技术说明

| 项 | 说明 |
|----|------|
| 形态 | 单个 HTML 文件，双击即可打开 |
| 依赖 | **零外部依赖**，不加载任何 CDN，完全离线可用 |
| 图表 | 自绘 SVG（趋势图、条形图、热力图） |
| 存储 | 浏览器 localStorage，键名 `growth_kit_v2` |
| 门禁 | 家长端 4 位 PIN（仅防误操作，非安全加密） |
| 兼容 | 手机 / 平板 / 电脑浏览器；可「添加到主屏幕」当 App 用 |
| 数据 | 全部留在本地，不上传、不注册、不联网 |

## 10. 下一步可选增强

按优先级排列，都可以后续再加：

1. **拍照存证**（打卡附一张照片，存 base64，注意 localStorage 容量上限约 5MB）
2. **家庭多设备同步**（需要一台常开设备做同步服务，或改用云端存储）
3. **每周自动生成周报推送给家长**（可做成定时任务）
4. **孩子端「今天只剩 3 件事了」的收尾提示**（降低半途放弃率）
5. **自定义徽章图案**
